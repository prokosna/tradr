### Definition of done
- [ ] Modify `identity.rs` to retain and expose an `Arc<dyn KeyStore>` in `IdentityState` so it can be passed to the transport.
- [ ] `lifecycle.rs` sets up the background environment:
      - Creates a `PosixVfs` and registers a Downloads directory as `RootId`.
      - Starts `QuicTransport` on `0.0.0.0:0` with the `KeyStore`.
      - Starts `mdns_sd::ServiceDaemon`.
      - Registers an mDNS advertisement (`ServiceInfo`) containing the device's `TxtRecord` and the transport's bound port.
      - Starts `MdnsSource::browse`.
      - Spawns `listener::run_listener` on the transport's `Incoming` using `tauri::async_runtime::spawn`.
- [ ] Tauri state holds the active `MdnsSource`, `QuicTransport`, and `PosixVfs`.
- [ ] `commands.rs` exposes `get_peers`: polls `MdnsSource` and returns discovered peers.
- [ ] `commands.rs` exposes `send_files(peer_id, files)`:
      1. Uses `MdnsSource` to find the peer's address.
      2. Dials the peer via `QuicTransport`.
      3. Handshakes on the control stream.
      4. Constructs a `TransferOffer` for the provided files (hashes them, creates sizes).
      5. Sends the offer and reads `TransferAccept`.
      6. Runs `send_file` for each accepted item based on `ItemResumption`.
- [ ] Register `get_peers`, `send_files` commands and the `lifecycle` startup in `lib.rs` `init`.
- [ ] Write tests verifying `send_files` against a mock receiver or via local loopback.

### Constraints
- Do not modify `tradr-core`. If that becomes necessary, raise a DCR and stop.
- Keep the UI (frontend drag-and-drop) out of this Work Item if it risks exceeding the size limit; we only need the Tauri backend commands.
- Do not use `std::thread::spawn` or `tokio::spawn` leaking handles; tie background loops to the Tauri app lifetime.
